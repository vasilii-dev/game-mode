# Ручная проверка на Windows

Проверяйте на Windows 10/11 x64 под обычной учётной записью, предпочтительно в отдельной виртуальной машине. Сначала сохраните работу и закройте приложения с важными данными. Для сценариев закрытия используйте тестовое приложение из этого репозитория. Не проверяйте защиту попыткой завершить системные процессы вручную.

```powershell
dotnet build src/GameMode.Windows -c Release
dotnet run --project tests/GameMode.Tests -c Release
dotnet build tests/GameMode.TestTarget -c Release
dotnet run --project src/GameMode.Windows -c Release
```

После сборки тестовый файл находится в `tests\GameMode.TestTarget\bin\Release\net10.0-windows\GameMode.TestTarget.exe`. Он выделяет 240 МиБ, заполняет физические страницы и показывает свой Working Set. Windows может вытеснить страницы; ориентируйтесь на фактический Working Set. В тестовом окне нет несохранённых документов.

## Первый запуск, настройки и трей

1. На первом запуске убедитесь, что показаны предупреждение о потере несохранённых данных, объяснение повторного запуска и предложение проверить исключения. Прочитайте и подтвердите их.
2. Без игры включите режим: статус **Ожидает**, серая иконка. Выключите кнопкой: **Принудительно выключен**, красная авторская иконка.
3. Откройте меню трея. Строка «Статус» недоступна как команда; ниже разделитель, «Настройки», «Проверить обновления», «Выход». Двойной щелчок открывает настройки.
4. Измените порог, интервал, исключения, правила игр и возврат. Закройте окно настроек — трей остаётся. Выберите «Выход», запустите снова и проверьте сохранённые значения.
5. Проверьте Tab/Shift+Tab, Enter/Space, фокус на кнопках, доступные названия элементов и диалогов. При масштабе Windows 100%, 150%, 200% иконки и текст читаемы; элементы не обрезаются.
6. Отключите анимации Windows в настройках специальных возможностей и перезапустите приложение. Смена статуса и панели должны работать без декоративного движения.

## Обнаружение и принудительное отключение

1. Запустите тестовую программу с 16 МиБ:

   ```powershell
   .\tests\GameMode.TestTarget\bin\Release\net10.0-windows\GameMode.TestTarget.exe --mib=16
   ```

2. Добавьте её в «Запускать режим при обнаружении» через список процессов. Проверьте полный путь и время последнего срабатывания. При включённом режиме статус становится **Включен**.
3. Отключите правило игры: статус **Ожидает**, очистка прекращается. Включите правило снова: **Включен**. Принудительно отключите режим большой кнопкой при работающей игре: **Принудительно выключен**.
4. Удалите тестовое правило, добавьте тот же `.exe` через диалог. Запуск файла по этому пути снова активирует режим.
5. Для реальных Dota 2, CS2 и Roblox проверьте соответствие исполняемому файлу, а не названию окна. Не используйте переименованные окна как доказательство.
6. С двумя обнаруженными играми закрытие одной должно оставлять режим активным. Когда последняя завершится, статус меняется на **Ожидает** и начинается возврат приложений.

Важно: один и тот же путь тестового файла, добавленный как игра, защищает все его экземпляры. Для проверки закрытия ниже удалите его из списка игр и используйте настоящую игру либо отдельную копию тестового приложения в другой папке как игровой триггер.

## Исключения и безопасное закрытие

1. Оставьте игровой триггер работающим. Запустите отдельный тестовый `.exe` по пути, не добавленному в список игр, с `--mib=240`.
2. Добавьте этот путь в исключения. На двух циклах проверки процесс остаётся открыт, несмотря на Working Set больше 200 МиБ. Посмотрите путь правила.
3. Удалите исключение при отсутствии других важных приложений. На следующем цикле Game Mode сначала запрашивает обычное закрытие тестового окна; процесс завершается, запись появляется в очереди и журнале.
4. Запустите тестовый файл с `--mib=16`. При фактическом Working Set ниже порога он остаётся открыт. Равенство порогу и строгое сравнение покрыты автоматическими проверками, поскольку рабочий набор настоящего процесса изменяется.
5. При включённом режиме игра и её связанные процессы, Game Mode, Explorer, службы и защищённые компоненты остаются открыты. Автоматические проверки политики подтверждают эти категории без действий над настоящими системными процессами.
6. Для проверки принудительного завершения запустите тестовый файл с `--mib=240 --ignore-close`. При отключённом принудительном завершении окно остаётся открытым и журнал объясняет результат. Закройте кнопкой внутри тестового окна. Затем повторите с разрешённым принудительным завершением: после периода ожидания процесс закрывается, журнал указывает принудительный способ.
7. Если доступа к процессу нет, Game Mode записывает понятную ошибку и пропускает действие; UAC без команды пользователя не появляется. Не используйте административные инструменты для обхода этой проверки.

## Возврат после игры

1. Разрешите возврат глобально и для тестового приложения. Закройте его через Game Mode и проверьте запись: путь, захваченные сведения и статус ожидания.
2. Закройте последнюю игру. Тестовое приложение запускается заново, окно запрашивается свёрнутым; запись и журнал показывают результат. Аргумент `--mib=240` сохраняется. Это новый процесс с новым PID и новым состоянием.
3. Повторите, но перед окончанием игры вручную запустите тот же путь. После игры второго экземпляра быть не должно; очередь объясняет пропуск из-за существующего процесса.
4. Повторите, выключив возврат для одной записи. После игры этот путь не запускается. Проверьте и глобальное отключение возврата.
5. Повторите, добавив уже закрытый путь в исключения до конца игры. После игры запуск запрещён, причина видна.
6. Если файл удалён/переименован, изменился, рабочая папка недоступна или аргументы не захвачены безопасно, запись не запускается; причина есть в очереди и журнале. Для этих сценариев используйте отдельную копию тестового приложения.
7. Приложения, закрытые пользователем, Task Manager или другим ПО, не должны появляться в очереди Game Mode. Неуспешная попытка закрытия тоже не создаёт разрешение на возврат.
8. Выход/авария Game Mode с очередью не должны порождать скрытый перезапуск при следующем запуске. Проверьте отображение прерванных записей. Сохранённая очередь нужна для прозрачности действий.

## Проверка обновлений и журнал

1. Вызовите «Проверить обновления» с доступной сетью. Для приватного репозитория без публичных выпусков ожидается понятное сообщение о недоступном источнике/отсутствии выпусков и возможность открыть страницу проекта. Нельзя писать «последняя версия», если источник не подтвердил это.
2. Отключите сеть и повторите: приложение остаётся отзывчивым, ошибка объяснена, ссылка на проект доступна.
3. Когда владелец опубликует публичный выпуск с распознаваемым номером версии, проверьте сравнение меньшей, равной и большей версий и открытие страницы. Не создавайте выпуск только для прохождения проверки.
4. Убедитесь, что журнал содержит обнаружение игры, обычное/принудительное закрытие, пропуски, результаты возврата и ошибки. Перед публикацией удалите приватные пути, аргументы и заголовки окон.

Запишите версию Windows, сборку Game Mode, выполненные пункты и любые пропуски. Автоматическое прохождение Core-тестов не заменяет эту проверку Windows API и интерфейса.

## Авторские ассеты, фон и окно «Авторы»

1. В безопасном режиме просмотра проверьте `--preview-state off`, `waiting`, `enabled`: рисунок и фон должны соответственно становиться красными, серыми и зелёными. Главная кнопка и текст статуса согласованы.
2. Отключите анимации Windows: смена цветов происходит сразу. Ни одно состояние просмотра не запускает мониторинг или закрытие процессов.
3. Откройте «Авторы» несколько раз: показывается одно отдельное окно с именем vasilii-dev и предоставленной аватаркой. Escape и «Закрыть» закрывают его, повторное открытие работает.
4. Откройте «О приложении» → «Предупреждение»: видны «Ахтунг, важно!», авторская иконка и текст, пояснение защищённых процессов и ограничения возврата. Повторное чтение не меняет согласие или включение режима. На первом запуске кнопка «Я согласен, поехали!» сохраняет согласие, оставляя режим выключенным до вашего нажатия.
5. Убедитесь, что «Лицензии» показывает GPLv3 и Apache 2.0. Служебные SVG и все PNG отображаются без сети. Ссылки GitHub открываются только по нажатию.

## Beta 0.1 QoL

1. Выберите несколько процессов Ctrl/Shift, измените поиск и добавьте их. Уже добавленные пути и несколько экземпляров одного .exe не создают дубликаты. В файловом диалоге также выберите несколько .exe.
2. В играх и исключениях выделите несколько строк, нажмите «Удалить» или Delete. Изменение других настроек и обновление обнаруженного пути не снимает выделение. В очереди возврата выберите несколько записей и нажмите «Не возвращать выбранные».
3. Для приложения с встроенной иконкой она видна в списке; для отсутствующего файла/файла без иконки подставного рисунка нет. Переключите состояние: навигация остаётся в центре.
4. Проверьте быструю прорисовку галочки и прокрутку. Нажатие на полосу прокрутки/клавиатура прекращают текущую анимацию; отключённые анимации Windows выполняют переход сразу.
5. Проверьте итог одного сеанса и несколько ошибок: не должно быть уведомления на каждое закрытие, повторные уведомления ограничены десятью минутами. Отключение уведомлений не отключает журнал.
6. «О приложении» → вниз → «Дополнительные настройки»: выключите/включите автозагрузку, проверьте только пользовательскую запись GameMode в HKCU Run. Запуск --startup при уже работающем экземпляре не показывает лишний диалог. При входе в Windows программа запускается в трее, если Windows разрешает эту запись. Ручная перезагрузка в автоматические проверки не входит.
7. Включите экспериментальный детект, запустите неизвестную списку игру Steam: статус и пояснение показывают источник Steam. Явно отключённое правило/исключение блокирует эту эвристику. Выключите эксперимент — обычные правила продолжают работать. ПО из Steam может давать ложное срабатывание; другие магазины пока не распознаются.

## Beta 0.1.1: интерфейс

1. В главном окне, списке процессов, авторах, предупреждении и лицензиях ползунки тонкие, тёмные и без стрелок. Проверьте колесо, перетаскивание, нажатие на дорожку, Page Up/Down, Home/End; в длинном текстовом поле также горизонтальную прокрутку. У краёв не должно появляться широкого системного ползунка.
2. Включайте и выключайте галочки мышью и Space. Видна короткая прорисовка в обе стороны, включая «Детект» и «Возврат»; быстрое повторное нажатие заканчивается правильным состоянием. Обновление журнала/процессов не должно уничтожать выбранную строку или галочку.
3. Пройдите интерфейс клавишей Tab: вместо большой белой рамки видна тонкая цветная обводка. Space/Enter и Ctrl/Shift продолжают работать. Поля памяти высотой 40 px скруглены, длинная подпись чекбокса переносится внутри панели.
4. Добавьте `.exe` с иконкой в игры. Для встроенных Steam/Roblox игр с доступной стандартной установкой иконка может появиться без запуска. Запустите игру, затем закройте: настоящая иконка и последний обнаруженный путь остаются в текущем окне Game Mode. После перезапуска Game Mode просмотр обнаруженного пути снова может требовать запуска игры; правило детекта не изменяется.
5. Во всех состояниях основная кнопка однотонная. Проверьте масштаб Windows 100/150/200%, узкое окно и отключённые системные анимации. Полный набор мониторов и настроек доступности проверяется вручную.
