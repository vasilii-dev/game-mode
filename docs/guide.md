# Руководство Game Mode — Beta 0.1.1

[← На главную](../README.md)

Game Mode — приложение Windows, которое живёт в системном трее и закрывает подходящие пользовательские приложения с большим потреблением физической памяти во время игры. Порог по умолчанию — **строго больше 200 МиБ Working Set**. Интервал проверки по умолчанию — 10 секунд.

**Закрытие может уничтожить несохранённые данные.** После игры Game Mode пытается запустить подходящие закрытые им приложения заново, но не восстанавливает их прежнее состояние. Перед включением проверьте исключения и сохраните работу.

## Возможности

- Три состояния: **Включен**, **Ожидает**, **Принудительно выключен**. Большая кнопка в настройках разрешает или запрещает режим; очистка начинается только при обнаружении включённого правила игры.
- Dota 2 (`dota2.exe`), Counter-Strike 2 (`cs2.exe`) и Roblox (`RobloxPlayerBeta.exe`) добавлены по имени исполняемого файла. Свою игру можно выбрать из запущенных процессов или указать конкретный `.exe`; пользовательские правила привязываются к полному пути.
- Отдельные списки исключений и игр: добавить, удалить, просмотреть путь, временно отключить правило игры, увидеть последнее срабатывание.
- Защита Game Mode, обнаруженных игр и связанных процессов, оболочки Windows, служб, системных каталогов, критических и защищённых процессов. Неполные сведения приводят к пропуску процесса.
- Обычный запрос закрытия окна перед принудительным завершением. Принудительное завершение можно отключить. Работа под обычной учётной записью; ошибки доступа объясняются в журнале без автоматического повышения прав.
- Очередь возврата с выбором для отдельных приложений. Доступные путь, аргументы, рабочая папка и сведения об окнах сохраняются перед закрытием; перезапуск проверяет исключения, дубликаты и безопасность исполняемого файла.
- Настройки между запусками, понятный журнал действий и проверка опубликованных выпусков проекта.
- Тёмный интерфейс с авторскими иконками и фоном для каждого состояния: зелёный — активен, серый — ожидает, красный — выключен пользователем. Отдельное окно «Авторы» с аватаркой vasilii-dev, управление с клавиатуры и короткие анимации с учётом настройки Windows. Иконки Windows подготовлены в размерах 16–256 px.

Game Mode не изменяет игровые файлы, приоритеты, настройки драйверов или служб. Суммарный Working Set закрытых процессов в интерфейсе — снимок на момент проверки, а не обещание такого же прироста свободной памяти: общие страницы и динамическое распределение памяти Windows влияют на результат.


## Beta 0.1.1: интерфейс

Общая тема `UI/Theme.xaml` используется главным окном и диалогами. Тонкий ползунок без стрелок занимает 6 px внутри полосы 8 px; вертикальная и горизонтальная прокрутка работают в списках, предупреждении, авторах и лицензиях. Системная белая рамка фокуса заменена тонкой цветной обводкой; управление Tab, Space, Enter и множественный выбор сохранены.

Чекбоксы размером 18 px используют меньшую галочку толщиной 1,6 px с прорисовкой за 140 мс в обе стороны. Переключение детекта и возврата обновляет существующие элементы, не пересоздавая их посреди анимации. Поля памяти скруглены и имеют высоту 40 px. Кнопка режима — однотонная для всех трёх состояний; карточки, наведение и выделение используют спокойную общую палитру.

Иконки игр извлекаются из `.exe`, как в исключениях. Для встроенных игр интерфейс также ищет файл в каталогах установки из манифестов Steam и локальных версиях Roblox, не запуская игру и не меняя правила. После обнаружения процесса его иконка и просмотр пути сохраняются до закрытия Game Mode. Если файл или иконка недоступны, подставное изображение не показывается. Политика мониторинга, закрытия и возврата процессов в этом обновлении не менялась.

## Удобство и дополнительные настройки

- В списках процессов, игр, исключений и возврата доступны Ctrl/Shift и Ctrl+A. Несколько .exe можно выбрать и в файловом диалоге. Поиск сохраняет выбранные программы; одинаковые пути не создают дубликаты правил.
- Иконки читаются из ресурсов настоящего .exe в фоне, с ограничением параллелизма и кэшем. Если иконки нет, подставная иконка не показывается.
- Галочки прорисовываются за 140 мс, прокрутка колёсиком использует короткое сглаживание. Анимации учитывают настройку Windows; мышь и клавиатура могут прервать прокрутку.
- Навигация закреплена по центру окна независимо от ширины статуса. Текущая версия показана в заголовке и на главном экране.
- Приложения закрываются по убыванию Working Set; защищённые процессы и исключения пропускаются.
- Уведомления ограничены итогом игрового сеанса и редкими ошибками, не чаще одного за 10 минут. При открытых настройках всплывающие уведомления подавляются. Все действия остаются в журнале.

«О приложении» → прокрутить вниз → **«Дополнительные настройки»**:

1. **Автозагрузка.** По умолчанию включена. После подтверждения предупреждения Game Mode регистрирует запуск текущего GameMode.exe с --startup в пользовательском ключе Windows Run. Администратор не нужен. Флажок удаляет или обновляет только запись GameMode; настройки режима сохраняются отдельно. Windows может задержать запуск или запретить его в Диспетчере задач. Приложение не обходит этот запрет. Переносимую папку нужно сохранять по постоянному пути; обычный запуск из нового места обновляет запись.
2. **Тихие уведомления.** Можно полностью отключить всплывающие уведомления, сохранив журнал.
3. **Экспериментальный детект Steam.** По умолчанию выключен и находится внизу дополнительных настроек. Использует локальные libraryfolders.vdf и appmanifest_*.acf, полный путь запущенного .exe, проверенное пользовательское окно и данные безопасности. Индекс библиотек обновляется раз в минуту. Проверяет только Steam, может считать ПО из Steam игрой; не является универсальным классификатором. Исключения и явно отключённые правила не включают режим через экспериментальную эвристику. Найденные приложения и связанные процессы защищены от закрытия; автоперезапуск таких файлов запрещён.

Проверки интерфейса работают с фиктивной платформой, не меняют автозагрузку и не закрывают пользовательские процессы:

```powershell
dotnet run --project tests/GameMode.WindowsChecks -c Release -- ui
```

## Требования и запуск

Для работы: Windows 10/11 **x64**. Для сборки: **.NET 10 SDK** с Windows Desktop SDK. Выбран C#/.NET с WPF: это нативное окно Windows, доступ к Win32 для процессов и стандартный системный трей без браузерного движка. Сторонние NuGet-пакеты для приложения и тестового набора не нужны.

Из корня репозитория:

```powershell
dotnet build src/GameMode.Windows -c Release
dotnet run --project tests/GameMode.Tests -c Release
dotnet run --project src/GameMode.Windows -c Release
```

Для отдельной переносимой папки с включённой средой выполнения:

```powershell
dotnet publish src/GameMode.Windows -c Release -r win-x64 --self-contained true -o artifacts/GameMode
.\artifacts\GameMode\GameMode.exe
```

Сборка без `--self-contained true` требует установленной .NET 10 Desktop Runtime x64. Запускайте опубликованный `.exe` вместе со всеми файлами из папки публикации.

На первом запуске приложение объясняет последствия закрытия и предлагает проверить исключения. Сохраните работу, добавьте важные приложения и включите режим. Закрытие окна настроек оставляет приложение в трее. Чтобы завершить его, выберите **Выход** в меню трея.

## Как работает защита и возврат

Каждый цикл получает снимок процессов и данные безопасности. Правила игр сопоставляются с исполняемым файлом, а не заголовком окна. В активном режиме приложение рассматривает процессы текущего пользователя с проверенными данными и пользовательскими окнами, чей Working Set строго превышает установленный порог. Игра, процессы из исключений и защищённые компоненты пропускаются. Нельзя гарантировать безопасность произвольного стороннего приложения по одному имени; консервативные проверки намеренно оставляют часть процессов открытыми.

Перед запросом закрытия сохраняются доступные сведения для повторного запуска. Непосредственно перед обычным и принудительным закрытием Windows-платформа повторно проверяет личность процесса, защиту и разрешение режима. В очередь возврата попадают только подтверждённо закрытые Game Mode процессы. Если закрытие не удалось или процесс сменился, приложение не считается закрытым Game Mode.

После завершения всех обнаруженных игр проверяется очередь: включён ли возврат глобально и для этого приложения, доступен ли исполняемый файл, сохранилось ли его содержимое, есть ли безопасные аргументы и рабочая папка, нет ли работающего экземпляра или нового исключения. Запуск запрашивается свёрнутым. Приложение может игнорировать этот запрос; окна сворачиваются по возможности. Службы, системные и неподходящие процессы повторно не запускаются. При недостаточных данных причина показывается в очереди и журнале.

Принудительное отключение прекращает очистку; очередь возвращается после окончания игры. Выход из Game Mode и аварийное прерывание не являются основанием для скрытого автоматического перезапуска при следующем старте: оставшиеся записи отмечаются для диагностики. Очередь и журнал не являются сохранением состояния приложений.

Настройки и журналы находятся в локальной папке пользователя `%LOCALAPPDATA%\GameMode`. Данные запуска и заголовки окон могут содержать приватную информацию. Перед отправкой журнала удалите такие сведения. Game Mode не отправляет журналы на сервер.

## Проверка обновлений

Пункт трея **Проверить обновления** использует опубликованные GitHub Releases этого репозитория: [последний выпуск](https://github.com/vasilii-dev/game-mode/releases/latest). Проверяются только стабильные выпуски: предварительные Beta этот источник не возвращает. Программа сравнивает доступную версию и предлагает открыть страницу выпуска. Самостоятельная установка или замена файлов не выполняется. Если выпусков пока нет, репозиторий приватный, сеть недоступна или версия не распознана, приложение сообщает об этом; успешная проверка не имитируется. Проверка не хранит GitHub-токены и не получает права вашего подключения GitHub MCP. Для приватного репозитория страницу можно открыть вручную в браузере с вашей авторизацией. Наличие исходников или CI-артефакта не означает наличие опубликованного выпуска.

## Проверка поведения

```powershell
dotnet run --project tests/GameMode.Tests -c Release
dotnet build tests/GameMode.TestTarget -c Release
```

Автоматические проверки работают с поддельными процессами: игры, родственники, исключения, системные компоненты, неизвестные сведения, строгий порог, переходы состояний и возврат без дубликатов. Они не завершают реальные процессы. Ручные сценарии для трея и Windows API, в том числе контролируемое приложение с выделенной памятью, описаны в [docs/manual-testing.md](manual-testing.md).

## Ограничения Windows

- Working Set содержит общие и частные физические страницы; это не Private Bytes и не полный объём виртуальной памяти.
- Windows может не разрешить чтение пути, командной строки, критического статуса, PEB или данных защищённого процесса. Такой процесс пропускается. Недоступная инвентаризация служб блокирует очистку всего цикла.
- Захват рабочей папки и аргументов через PEB рассчитан на поддерживаемую x64-платформу; неполные либо небезопасные сведения запрещают возврат. Упакованные приложения, специальные служебные режимы, отсутствующие файлы и изменённые исполняемые файлы могут не подлежать повторному запуску.
- Запрос обычного закрытия не означает успешного сохранения данных. Диалог сохранения может остаться открытым; разрешённое принудительное завершение после ожидания может уничтожить данные.
- Проверки повторяются перед действием, но Windows не предоставляет одной транзакции для снимка всех процессов, их закрытия и последующего запуска. Приложение отказывается от действий при обнаруженной неоднозначности.
- Состояние окон, документы, вкладки, игровые сессии и несохранённая работа не восстанавливаются. Свёрнутое окно — запрос и последующая попытка, не гарантия поведения сторонней программы.
- Запуск без администратора намеренный. Game Mode не повышает права для обхода защиты и не завершает процессы при отказе в доступе.
