# Участие в Game Mode

Спасибо за помощь. Перед изменением посмотрите README и инструкции ручной проверки в `docs/manual-testing.md`. Небольшие изменения лучше присылать отдельными pull request; для больших изменений сначала опишите сценарий и ограничения в issue.

## Локальная работа

Потребуются Windows 10/11 x64 и .NET 10 SDK. Соберите приложение и запустите проверки:

```powershell
dotnet build src/GameMode.Windows -c Release
dotnet run --project tests/GameMode.Tests -c Release
```

`GameMode.Tests` — небольшой исполняемый набор проверок без стороннего тестового фреймворка. Ошибка завершает его с ненулевым кодом. Он использует поддельную платформу процессов и не завершает приложения на компьютере.

## Правила изменений

- Сохраняйте консервативные проверки безопасности. Неизвестный процесс, недоступный путь, неполная инвентаризация служб или отсутствие подтверждения личности процесса должны запрещать закрытие.
- Проверяйте PID вместе со временем запуска. PID может быть повторно использован Windows.
- Защищайте игры, их родственников, исключения, Game Mode и критические компоненты при каждом действии, включая повторную проверку непосредственно перед закрытием.
- Повторный запуск разрешён только для подтверждённо закрытых Game Mode приложений с проверенными сведениями запуска. Не обещайте восстановление несохранённых данных.
- Не добавляйте постоянное требование администратора, автоматическое повышение прав, скрытую отправку журналов или отключение защит Windows.
- Не обходите настройки пользователя и не запускайте приложения из новой версии списка исключений.
- Сохраняйте доступность клавиатуры, контрастность и поддержку системной настройки анимации. Пользовательские тексты приложения — на русском.
- Не усложняйте архитектуру без конкретной потребности. Платформенные операции остаются в Windows-проекте, политика и состояние — в Core.

Для изменений политики добавьте проверку в `tests/GameMode.Tests`. Изменения трея, окон и Windows API проверьте на Windows по подходящим сценариям из ручного плана. В pull request укажите выполненные проверки и ограничения; непроверенное не называйте проверенным.

## Диагностика и конфиденциальность

Журнал повторного запуска может содержать пути, аргументы запуска, рабочую папку и заголовки окон. Они могут включать приватные имена файлов или токены. Перед публикацией удалите такие данные. Не присылайте пароли, ключи API или полный необработанный журнал.

Если обнаружен способ завершить защищённый процесс, до исправления отключите режим в своей установке. Опишите минимальный безопасный пример без приватных сведений. Отдельный приватный канал для сообщений о безопасности владельцем пока не указан.
